Code behavior and measurement limits

  • The current goBILDA ZIP includes an autonomous example. Its route launches for ten seconds, then requests a −120 mm move; it is not a vision auto.
  • The autonomous routine checks both drive encoders and limits each command. Target/shot failure stops the mechanisms, reverses its measured tag-positioning movements, and follows the parking path. Drive or return-path failure stops the run because position is uncertain.
  • SDK 12 reports the selected pose angles in degrees. Use shared pose fields for measurements and cluster metadata to select the target.
  • No pose can mean missing tag-size/library metadata. Lens calibration affects pose accuracy; an inaccurate camera can still return pose values.
  • Qualify a shooting range through measured trials. Camera-frame XY range differs from floor tape distance when the camera is tilted.
  • Moving hive tags support relative aiming. They do not make encoder travel into reliable field localization.
  • The bottom of the HIVE is 30.6 inches above the TILES (Figure 9-10, §9.6.2). Use the labeled reference points when planning clearance.

Plan the calibration before enabling motion

At Meeting 4, trace these steps and assign future tests using the documentation. Carry out the physical checks only after the kit arrives and the robot is assembled.

  1. Baseline: confirm exact motor models, ports, directions, encoder wiring, wheel/gear sizes, CRServo types, neutral, release, Stop, and restart. Match left_drive, right_drive, intake, launcher, windmill, left_intake_servo, and right_intake_servo.
  2. Camera: add Webcam 1, verify calibration at 640×480 and actual printed dimensions, and record mount position/pitch. Use the full BIOBUZZ cluster geometry for aiming. M3's single sample tag 584 is a telemetry target, not an aim target in this draft.
  3. Select and check: during INIT, use gamepad 1 D-pad left for RED or right for BLUE; up for the far-side cell (opposite the audience) or down for the audience-side cell. Select both and check Driver Station telemetry before Start. The SDK maps these to RED SCORING (30–33), RED AUDIENCE (34–37), BLUE AUDIENCE (38–41), or BLUE SCORING (42–45). Confirm the chosen cell is upward-facing; detection alone does not establish this. Autonomous locks both selections at Start. TeleOp locks alliance, but allows a new up/down press to change cells while A and RB are released. Release and press the D-pad again if a change was blocked. Starting without a complete selection requires Stop and INIT again for assisted targeting. Selection does not change the calibrated drive route.
  4. Sign and loss: with mechanisms empty, confirm that a target to the left produces positive bearing and a small left turn reduces the error. If error grows, stop. Cover the target, show the wrong cluster, disconnect the camera, and release A. Missing/stale target while holding A must stop drive; releasing A restores sticks.
  5. Tune alignment: test the proposed gain and turn cap one change at a time. Alignment requires ±2° for 0.3 seconds; frame age must be at most 0.25 seconds. These are draft test settings. Measure camera-to-launcher offset; tag center is not automatically the correct shooting trajectory.
  6. Measure the shot: record range, a consistent tape reference, offset, cell state, requested/actual velocity, battery, hits, misses, and tips. Qualify one narrow range window at the matching vendor starting velocity of 1250 ticks/s; do not extrapolate. Populate range limits before enabling assisted feed, then test every gate and button release.
  7. Measure travel: compare both wheel tick deltas with actual loaded travel over repeated runs. Set ticks/inch and a signed route distance for a marked start. Both wheels must settle within the draft 0.5-inch encoder tolerance; failure must stop at the four-second drive deadline. Tag positioning has a four-second deadline. Then trace stable-speed spin-up and one timed shooting burst. Test Stop in every phase, target/speed loss, and a wheel-failure case. DRY_RUN never fires and includes the parking leg. SHOOT_AND_PARK requires qualified route and shot settings; the Markdown guide supplies the full calibration procedure.
  8. Accept or revise: proposed evidence is five repeatable drives within the team's tape tolerance, five stable aim trials from each side, and all loss/release/Stop tests passing. Repeat after mount or battery changes. Record LEAVE/PARK from actual end position, not a constant in code.

Practice how to measure

Calibration means measuring this robot and putting the result into its settings. Tuning means changing one setting, repeating the same test, and comparing results. Telemetry is the live text on the Driver Station; encoder ticks count motor rotation.

  1. Mark a fixed pointer on the chassis, its floor start position, and the starting heading. Assign a driver, recorder, and measurer. Measure only after Stop and after mechanisms stop moving.
  2. For an empty straight-drive test, record both encoder counts and measure actual pointer travel with a tape measure. Divide each count by actual inches. Example only: 1080 ticks ÷ 23 inches = 46.96 ticks/inch. Repeat three times before changing the setting; investigate curves or disagreement between wheels.
  3. For aiming, record the bearing before holding A and after it settles. If the error grows, Stop and check direction. If it wiggles across the target, reduce gain slightly and repeat from the same marks. Change only one number at a time.
  4. For shooting, mark several nearby positions and record SDK range plus hits out of five at each. Use only a repeatedly successful interval for the range limits. Record tips separately from hits.

The Markdown guide’s beginner lab gives the exact OpMode, button sequence, telemetry labels, worked calculations, recording tables, and next change for the exercises, including IMU-controlled turns, launcher offset, burst timing, and whole-route validation. At Meeting 4, use its example numbers on paper; actual measurements wait for the assembled robot.

Configure heading and check the start

The Control Hub IMU supplies heading; wheel encoders supply distance. HubHeading assumes logo UP and USB FORWARD until the team checks the actual mounting. Use FIRST’s orientation diagrams, then use the calibration OpMode’s INIT telemetry to check a hand-turned 90° right/left rotation before confirming the mounting. Positive heading means right in our code. Start sets zero at the marked starting direction.

turnDegrees finishes using IMU heading, and straight driving corrects heading error. Telemetry estimates local X forward and Y right from the selected start; wheel slip still limits accuracy. Start A is a candidate audience-perimeter pose and B an opposite-audience-perimeter pose, each on our alliance side with its front inward. Verify the complete legal footprint and measure each exact mark.

An optional measured AprilTag range/bearing check during INIT can catch a misplaced robot when the hive remains in the same known starting state. It never moves the robot in INIT or resets field coordinates. The Markdown guide explains recording repeated readings and enabling the check for one route card. Moving hive tags cannot serve as an unconditional fixed field reference.

Choose and measure an autonomous route

During INIT, D-pad left/right selects alliance and up/down selects cell. A selects start/shot/park A; B selects start/shot/park B. Press and release X to cycle DRY_RUN, SHOOT_AND_PARK, and PARK_ONLY. Read the complete route on the Driver Station. These are team-defined marked poses, not official start boxes. Match modes require a qualified route card; supplied numbers are empty-floor practice values.

Use G304 and Figure 11-1 to choose a legal start and Figure 10-7 to mark the final parking footprint. Draw the starting heading, shooting pose, parking turn, and parking pose. Measure the route using the same chassis pointer at each mark. Plan space for the alliance partner.

StarterDrive.driveInches and turnDegrees start one motion; repeated update calls check completion without blocking Stop or telemetry. StarterLauncher handles intake, spin-up, bounded shooting, and stop. Use BIOBUZZ Measure Drive or Turn to test just one empty-robot 24-inch drive or 90° turn before combining a route. Record actual angle with floor heading lines and a protractor.

After tag positioning and shooting, the robot reverses its recorded turns and straight movement to return toward the approach pose before parking. This needs measurement because tires can slip. The 28-second deadline and a parking-time reserve limit shooting time. A completed command does not prove the robot is parked: verify that its footprint is partly in the LOADING ZONE and clear of the wall at AUTO end. Test each route independently.

driveToTag turns toward the selected cluster, moves straight to a requested camera range, then turns to the shooting offset. It stops on stale/missing tags, timeout, or travel limits. Use BIOBUZZ Measure Tag Approach for the empty-robot test and measured return. The Markdown guide’s Exercise 2B explains the telemetry, small gain changes, forward/backward trials, and how to measure return error. Wheel slip can still leave a position error; verify the actual parking footprint.

Student trace: predict outputs when A is held and the tag disappears; when the bumper is released; when range is outside the measured window; and when only one encoder reaches the target. Explain which check prevents the next action.

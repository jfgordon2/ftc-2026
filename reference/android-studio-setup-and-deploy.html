Words used in the daily path

Project
The complete set of files Android Studio opens to make the robot app. The project folder used here contains both TeamCode and FtcRobotController.
Build
Ask Android Studio to check the Java code and turn it into an app the Control Hub can run. The Build output reports success or an exact error message, file, and line.
Deploy
Install the built Robot Controller app, including the team's code, on a selected Control Hub.
Target
The named Control Hub that Android Studio will install the app on. Read its name before running so the app goes to the intended robot.
Run configuration
The saved Android Studio choice that says which app to build and install. For this course, choose TeamCode.
Robot Controller app
The app on the Control Hub that runs the team's robot programs and communicates with the Driver Station.
OpMode
A robot program for one activity. The Driver Station displays enabled OpModes by name.
INIT
The Driver Station control that prepares the selected OpMode before Start.
Telemetry
Messages and values the robot code sends to the Driver Station so the team can see what the program is doing.
Evidence
The exact visible result that supports what the team says happened, such as a screen message, telemetry value, or stopped motor.
Start
The Driver Station control that tells an initialized OpMode to begin its active instructions.
Stop
The Driver Station control that ends the OpMode. Press it immediately if the robot does anything unsafe or unexpected.

Track 1: Mentor preflight before Meeting 1

Complete every item before students arrive. Installation, repository download, and the first Gradle sync are not Meeting 1 student tasks.

  1. Read the pinned FTC SDK v12.0 release and its requirements. SDK v12.0 requires Android Studio Narwhal 3 Feature Drop or later; the pinned SDK requirement controls if an evergreen page differs.
  2. Follow the official Android Studio installation instructions. Install required components and open Android Studio once.
  3. Follow Fork and Clone From GitHub. Fork into the team organization, create the team development branch from tag v12.0, and clone the team repository to every laptop.
  4. Open the repository root, not TeamCode or another nested directory. The selected folder must contain both TeamCode and FtcRobotController. Allow the first Gradle sync to finish and prove TeamCode builds.
  5. Follow FTC Docs Before Writing Code: update, name, and pair the Control Hub and Driver Hub; keep Robot Controller and Driver Station on the same season version; and confirm the intended hardware configuration is active.
  6. Connect a charged 12 V battery, power the Control Hub, connect a known-good data cable to the Control Hub USB-C port, not Mini USB, select the target in Android Studio, and run TeamCode. Prove the Robot Controller app installs and reconnects.
  7. On the Driver Station, prove the prepared enabled OpMode appears and completes INIT, telemetry inspection, Start, and Stop with no unexpected motion.
  8. Record the proven laptop, cable, target name, Robot Controller and Driver Station versions, saved hardware configuration in use, and OpMode. Keep a second data cable and the proven project version available.

Recovery before students arrive

  • Sync fails: preserve the first Gradle Sync error and confirm the project root and SDK-required Android Studio version before changing settings.
  • No target: record Control Hub power, battery state, cable/port, and Android Studio target list; retry with the proven data cable.
  • Wrong target or install fails: stop, capture the exact deployment message, select the named team Control Hub, and repeat the official build/install procedure.

Track 2: Student workflow during Meeting 1 and normal meetings

Driver operates; navigator reads, points to each visible result, and records it. Swap roles before the next cycle.

  1. Open the project: open the mentor-prepared repository root so Android Studio loads the complete app. Success: the project panel shows both TeamCode and FtcRobotController.
  2. Find the team OpMode: expand TeamCode/src/main/java/org/firstinspires/ftc/teamcode and open the copied team file. This keeps team changes separate from official samples. Success: the editor path begins with TeamCode, not FtcRobotController.
  3. Build before robot contact: explain the intended change, build TeamCode, and open the Build output. This catches code errors before installation. Success: Build output reports success. If it fails, copy the first error's exact text plus its linked team-code filename and line number.
  4. Make the test area safe: secure the robot and battery, clear moving parts, and name the Driver Station and emergency-stop owners before applying power. Success: both owners are named and a second student confirms the robot, battery, wires, wheels, and mechanisms cannot move unexpectedly.
  5. Power and connect: with the Control Hub off, connect the charged 12 V battery; switch it on; then attach the known-good data cable to the Control Hub USB-C port, not Mini USB. This gives Android Studio a powered data connection. Success: the Hub status light is on and the Driver Station shows a Robot Controller connection.
  6. Select the target: choose the team's named Control Hub in Android Studio so the app goes to the intended robot. Success: Android Studio displays that exact Hub name as the connected target.
  7. Install the app: run the TeamCode run configuration. Android Studio builds and installs the complete Robot Controller app containing the team's code, not only the open Java file. Success: the Run window reports installation completed and the Driver Station reconnects to the Robot Controller.
  8. Select the intended OpMode: on the Driver Station, choose the copied, enabled team OpMode so the test runs the code you inspected. Success: its exact expected name appears as the selected OpMode. If it is absent, stop and record that fact.
  9. Use INIT: call robot live; after everyone answers clear, press INIT. This prepares the OpMode and lets you inspect its first output before motion. Success: the expected INIT telemetry appears and the robot remains in the predicted safe state.
  10. Use Start: press Start only after INIT output is correct. This begins the OpMode's active instructions. Success: the expected running telemetry and predicted robot behavior appear.
  11. Use Stop: press Stop at the written stopping point or immediately for an unsafe or unexpected result. Success: the OpMode ends and commanded motion stops. Say stopped, switch off the Hub, and disconnect the battery before contact.
  12. Record the visible results: write the exact Build status, target name, Run-window install message, selected OpMode name, INIT telemetry, running telemetry, and what changed after Stop. These details show where a later failure began; do not replace them with a vague failure note.

Daily deploy checklist

  • Open repository root; find TeamCode/src/main/java/org/firstinspires/ftc/teamcode.
  • Review the intended team-code change; keep official samples unchanged.
  • Build TeamCode; inspect Build output and stop on the first error.
  • Secure and clear the robot; connect charged 12 V power.
  • Connect through Control Hub USB-C and select the named target.
  • Run TeamCode; confirm Robot Controller app install and RC/DS reconnection.
  • Select the enabled copied OpMode; INIT and inspect telemetry.
  • Start, verify expected telemetry/behavior, then Stop and make safe.
  • Record the exact visible result and pass/fail.

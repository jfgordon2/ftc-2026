Robot and Control System

OpMode
A robot program for one activity. Example: choose Drive Practice on the Driver Station before pressing INIT.
TeleOp
An OpMode in which drivers use gamepads to control the robot. Example: moving a stick commands the drivetrain during driver-controlled play.
Autonomous
An OpMode that follows programmed instructions without gamepad driving. Example: after Start, the robot drives forward for a measured distance and stops.
Configuration
The saved list that connects each Hub port and device type to an exact name. Example: the motor on port 0 is saved as left_drive.
hardwareMap
The code lookup that connects a configured device name to a Java variable. Example: hardwareMap.get(DcMotor.class, "left_drive") finds that configured motor.
Telemetry
Messages and values that robot code sends to the Driver Station. Example: display the launcher speed while testing it.
INIT
The step that prepares the selected OpMode before Start. Example: press INIT and confirm the status message before anyone presses Start.
Encoder
A sensor that reports rotation as counts, often called ticks. Example: compare drivetrain encoder counts before and after a measured roll.

Programming

Compile / build
Check source code and turn it into software the control system can run. Example: build after editing and use the reported file and line to fix a missing semicolon.
Deploy
Install the built Robot Controller app on the selected Control Hub. Example: connect the laptop to the correct Hub and run TeamCode.
Loop
Instructions that run repeatedly while an OpMode is active. Example: each loop reads the gamepad and updates motor power.
Stop condition
A check that ends an action instead of letting it run forever. Example: stop driving when the target is reached, time expires, or the OpMode is no longer active.
Threshold
A measured boundary used to make a decision. Example: feed a game element only when launcher speed is above the tested threshold.
State
The robot's current named step or condition. Example: a mechanism changes from WAITING to FEEDING without freezing drivetrain control.

Testing and Evidence

Fixture
A guide or support that holds something in a repeatable, safer position. Example: place the robot against a marked starting fixture before every autonomous run.
Test stand
A stable setup that secures one component or subsystem for controlled testing. Example: clamp the motor test stand before applying low power.
Retest
Run the same check again after one change. Example: repair a loose connector, then retest with the same battery and steps.
Baseline
A known-working result or version used for comparison. Example: compare a new TeleOp change with the version that passed three complete runs.

Git and Recovery

Diff
A view of exactly what changed between two code versions. Example: check that a diff changes one motor constant and nothing unrelated.
Commit
One saved set of understood changes in Git history. Example: commit the new slow mode after both test cases pass.
Tag
A fixed name attached to one exact commit. Example: tag the tested event version event-2026-10-24.
Clone
A complete working copy of a repository made in a new folder. Example: clone the team repository on a backup laptop and build the event tag.

Event Readiness

Fallback
The rehearsed backup used when a primary feature, device, or person is unavailable. Example: a backup student restores and deploys the tagged code from a clean clone.

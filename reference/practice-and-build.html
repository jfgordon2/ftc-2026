BIOBUZZ / Practice and build plan

Learn on our robots. Build for BIOBUZZ.

Start with last season’s assembled REV and goBILDA StarterBots. Use them to learn while we build a competition robot with a launcher.

Which robot are we using today?

Give the robots clear names: REV practice, goBILDA practice, and BIOBUZZ build. Write the robot name, configuration, and source version on every test record. Record modifications to either practice robot.

Use each practice robot’s saved 2025-2026 program and configuration after the mentor checks them. Back them up before changing software or hardware. Check the selected SDK and Driver Station/Robot Controller versions before deploying. New-season vendor code does not become compatible just because the brand matches.

The lessons’ 2026-2027 REV and goBILDA examples are reading references. Run one only on its matching assembly. For a modified practice robot or our own BIOBUZZ design, use a team-adapted program: map the actual parts, use their documentation, and test the changed behavior. An exact StarterBot match is not required to learn or build a custom robot.

One coach, one powered station: one pair operates with an independent Stop owner while other pairs code, record results, or work on disconnected hardware. Rotate roles. Do not run both practice robots at once without separate qualified supervision.

Build a little each meeting

Meetings 4-13 reserve 35 minutes inside the three-hour meeting for build work. Choose one achievable task, assign a builder and checker, and leave the robot in a documented state. If a milestone takes longer, carry it forward and keep learning on a practice robot. Finish safety checks and testing before treating any new part as ready.

Launcher commitment: launching stays required in the BIOBUZZ plan. If it is unfinished, record “required — not ready,” keep its outputs disabled, and schedule the remaining work. Do not drop it from the plan to claim readiness. A separately tested driving-only autonomous routine remains a useful fallback.

Keep practice available: do not dismantle both old robots at once. Agree which robot stays usable before transferring parts. After mechanical changes, revise the robot record and repeat affected tests before using previous settings.

Moving code to another robot

  1. Save the working source and configuration for the original robot.
  2. On the new robot, repeat the identity and motor checks from Meetings 1-2. Check every name, port, direction, and motor type.
  3. Review each copied method. Replace robot-specific gearing, dimensions, limits, positions, and launcher settings using the new robot’s parts and measurements.
  4. Test zero output, one actuator at a time, release, conflicts, and Stop on support before travel or launching.
  5. Repeat the relevant TeleOp and autonomous tests. Label results with the new robot and configuration; do not copy old passing results.

Meetings 9-11 may continue on a qualified practice robot if the new build needs more time. Before event qualification, repeat these checks and the required routines on the BIOBUZZ robot. Meetings 12-13 use the actual launcher being studied; their results apply only to that assembly.

Connect practice to this game

Use Meeting 4’s current-rule checklist to choose legal collection, garden, hive, flower, and parking activities. Start autonomous planning with a small useful objective, such as LEAVE, before adding launcher actions. Check the current FIRST manual and updates; old scoring rules and old game pieces do not establish BIOBUZZ performance.

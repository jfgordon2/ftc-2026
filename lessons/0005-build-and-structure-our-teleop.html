Today’s goal

Leave with a launcher speed table we measured ourselves and one autonomous path that ends inside a taped parking box.

We do not have a field or the new robot yet, so we build a practice field from tape: a rectangle on the wall for the hive opening and lines on the floor for the start and the parking zone. We use one of last season’s practice robots. The numbers we find today belong to that robot. The steps, the worksheets, the tape layout and the code are what we reuse on the BIOBUZZ robot.

Start here

  1. Build the practice field. Tape the wall target and the floor lines. Use the measurements below.
  2. Tune the shooter. Shoot five balls, count hits, change the speed one step, repeat. Shooter steps.
  3. Measure a drive and a turn. Ask for 24 inches and 90 degrees, then check with a tape measure. Drive steps.
  4. Build the auto path. Type three numbers into one route, run it, measure where the robot ends. Auto steps.
  5. Save. Put the numbers that worked into the code and save it. Save your work.

One robot runs at a time. While one pair works at the robot, the other students tape the route, graph the shooting results, or read the code for the next step. Swap jobs after every five shots or every test run.

Before power

  • Everyone stands behind the robot when the launcher can spin. Nobody stands between the robot and the wall.
  • One student drives. A different student keeps a hand near Stop on the Driver Station and may press it at any time without asking.
  • Press Stop and wait for the wheel to stop before you load balls, pick up balls, measure, or touch the robot.
  • Clear a jam only with the robot switched off.
Stop first: if the robot goes the wrong way, something is loose, a ball jams, or the numbers on the screen look wrong, press Stop. Then work out why.

Steps and worksheets

Words you need

Ticks per second: how fast the launcher wheel spins, counted by its encoder. Our code and goBILDA’s code both ask for launcher speed this way. Camera range: the distance the camera reports to the AprilTags, in inches. Interpolate: pick a value between two measured points. Route: the list of steps for one autonomous path: drives, turns, and aim-and-shoot. IMU: the sensor in the Control Hub that tells which way the robot faces.

Build the practice field

The wall stands in for our hive. The sizes come from the game manual, so a shot that goes through the tape rectangle is aimed at the right height and width for the real opening.

Tune the shooter

Program: Tune Shooter (TuneShooter.java). Read its loop() before you drive it. It has five numbered parts.

ControlWhat it does
D-pad during INITChoose the target: LEFT then DOWN for RED AUDIENCE.
SticksDrive slowly to place the robot.
Hold AThe robot turns to face the tags by itself.
D-pad UP / DOWN after StartLauncher speed up or down by 25 ticks per second for each press.
Hold right bumperSpin the launcher. The robot will not drive while it spins.
Tap YOne short shot. The feeder runs for a moment once the wheel is at speed.
  1. Before the first shot, read the Battery line on the Driver Station during INIT and write the voltage on the worksheet. If it says SWAP or CHARGE, change the battery. Press Stop and INIT again now and then to re-check; after a swap, shoot one finished row again.
  2. Put the front bumper on the 34-inch mark, on the center line, facing the rectangle. Hold A until the robot stops turning, then let go.
  3. Load the balls. Hold the right bumper. When the screen says At speed: true, tap Y once for each ball. Shoot five balls at this speed.
  4. The recorder writes one row: the mark, the camera range and speed from the screen, how many of the five went through the rectangle, and where the misses went.
  5. Change one thing:
    • Mostly low: speed up one step.
    • Mostly high: speed down one step.
    • Left or right: aim again. Do not change the speed.
  6. Keep going until at least four of five go through. Shoot five more at the same speed to check. Circle that row.
  7. Move to the 26-inch mark, then the 18-inch mark, and find the circled row for each.
  8. Graph the three circled rows: camera range across the bottom, speed up the side. Does the line go up as the robot moves back?

Put the table in the code

Open ShooterCalibration.java. Type the circled rows into the two lists, closest range first. Each range lines up with the speed below it.

// Made-up numbers to show the shape. Use your own circled rows.
public static final double[] RANGE_INCHES           = {38, 46, 54};
public static final double[] SPEED_TICKS_PER_SECOND = {1100, 1175, 1250};

Between two rows the code interpolates. With the made-up rows above, a range of 42 inches is halfway between 38 and 46, so the speed is halfway between 1100 and 1175: about 1138. Outside the rows the robot refuses to shoot. It never guesses.

No camera? Set USE_CAMERA = false, aim by hand, and fill in the mark column only. The auto path below needs the camera.

Measure a drive and a turn

Program: Tune Drive. Take the balls out. No camera is needed.

  1. Put the robot on a tape mark with room ahead. Press INIT. Turn the robot a little to the right by hand: the heading number should go up. Put it back on the mark.
  2. Press D-pad UP to choose 24 inches forward. Press Start. Everyone stays clear.
  3. When it stops, write the left and right tick numbers from the screen. Press Stop. Measure how far the mark on the robot really moved.
  4. Work out ticks per inch: average ticks ÷ real inches. The code starts with about 45 (45.3 for a goBILDA robot, 44.6 for the REV robot). If yours differs by more than 1, type your number into TICKS_PER_INCH in Drive.java and test again.
  5. INIT again and press D-pad RIGHT for a 90-degree right turn. Check the result against a square corner taped on the floor.

If the robot curves, check for a dragging wheel before you change any numbers. If it stops and the screen says FAULT, read the reason on the screen.

Build the auto path

Program: Autonomous Route. A route is a list of steps in Routes.java. The robot does them from top to bottom. There are three kinds of step:

StepWhat the robot does
drive(inches)Drives that far. A negative number drives backward.
turn(degrees)Turns that much. Positive is right, negative is left.
aimAndShoot()Turns to face the tags, shoots if shooting is switched on, then turns back to the way it was facing.

The robot does not fix its distance from the wall. It shoots from wherever the drive before aimAndShoot() stops, using the speed your table gives for the camera range there.

Plan it on the floor

  1. Start position: back bumper on the start line, on the center line, facing the wall.
  2. Pick the shooting mark that worked best. Measure from the start position to that mark. That is your first drive, in inches.
  3. Put the robot on that mark and read the camera range from Tune Shooter. Check your speed table has a row closer and a row farther than that range.
  4. From that mark, decide the park turn (right is positive, left is negative) and measure the park drive into the box.

Type it in

In Routes.java change only the list that matches the printed target and Start A:

public static final Step[] RED_AUDIENCE_A = {
        drive(8),
        aimAndShoot(),
        turn(-90),
        drive(30),
};

The numbers 8, -90 and 30 are examples. Use yours. You can add or remove lines; keep the comma at the end of each one.

Run it empty

  1. No balls in the robot. Place it on the start position.
  2. INIT. D-pad LEFT then DOWN chooses RED AUDIENCE. Press A for Start A. Shooting should say DRY RUN. Check the route on the screen matches your list.
  3. Press Start and watch. The screen shows which step is running and a note about what happened last.
  4. When it stops, press Stop. Is the robot at least partly inside the box? How many seconds did it take?
  5. Change one number, build, and run again. Three runs in a row that end in the box means the path is done.

If it stops early

The screen saysTry this
Not moving: Hub direction is not confirmedAsk the mentor: the Hub direction check in Heading.java is not finished.
Not moving: MOTION_ENABLED is falseAsk the mentor: the drive-direction check is not finished.
Shot skipped: tags not lined up in timeThe camera could not see the tags, or could not centre them in 3 seconds. Check the tilt, the lighting, and that you chose the printed target. The route still carries on.
Shot skipped: speed table has no rows around … inchesThe first drive stopped outside the ranges you measured. Change the first drive, or measure another row.
Drive/turn timeoutA wheel did not reach its distance in 4 seconds. Look for something blocking a wheel, or split a long drive into two lines.

Extra: shoot during auto

Only after three good empty runs, and only with a filled-in speed table that covers the camera range at your stop. The mentor sets FEED_ENABLED to true in StarterRobot.java. In INIT, press X so Shooting says ON. Load the balls and stand behind the robot.

What this is worth in a match: moving off the field wall in AUTO is LEAVE, 3 points. Ending AUTO at least partly inside the LOADING ZONE is PARK, 5 points. Tipping the hive is 20. AUTO lasts 30 seconds; our program stops itself at 28.

Save your work

  • Your ticks per inch and your route numbers are in the code, and the code builds.
  • Commit with a short message, for example “Meeting 5 shooter table and route”.
  • Take one photo of the wall and one of the floor with the distances showing, so we can rebuild the practice field in ten minutes.
  • Keep the worksheets in the team binder.

Mentor preparation

Allow about 30 minutes before the meeting. The Meeting 5 setup guide has the reasons behind each measurement and what to recheck on a real field.

  1. Print the Meeting 5 packet at Actual Size / 100%: the worksheets and the two RED AUDIENCE tag sheets.
  2. Bring painter’s tape, a tape measure, a square corner or large protractor, cardboard for the wall, last season’s balls, and charged batteries.
  3. Robot choice: set ROBOT in StarterRobot.java to the robot on the table. PRACTICE_GOBILDA needs left_drive, right_drive, launcher, left_feeder, right_feeder in the Driver Station configuration. PRACTICE_REV needs leftDrive, rightDrive, flywheel, coreHex, servo. Both also need imu and Webcam 1.
  4. Hub direction: look at which way the Control Hub’s logo and USB ports face on the robot. Set LOGO and USB in Heading.java to match, then set MOUNTING_CONFIRMED = true.
  5. Drive direction: with the wheels off the floor, run Tune Shooter and push the left stick forward. Both sides should roll forward, slowly. Then set MOTION_ENABLED = true in StarterRobot.java.
  6. Launcher check: with no balls, run Tune Shooter, hold the right bumper, and confirm the measured speed climbs to the requested speed. Decide whether the 1800 ticks-per-second cap in ShooterCalibration.java suits your space. The REV robot’s normal speed is 1300, so it starts closer to the cap.

Leave the launcher’s PIDF numbers alone today. Meeting 13 covers them. Check the current FIRST manual and team updates before each meeting; this lesson was checked against Team Update 03.

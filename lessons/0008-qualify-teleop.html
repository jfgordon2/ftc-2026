Today’s goal

Leave with a TeleOp that completed the whole two-minute routine three times in a row, or a short list of exactly what stops it.

A robot that works once is a demo. A robot that works three times in a row with different drivers is ready for a match. Today nobody adds features. We run, count, and fix only what breaks.

Start here

  1. Agree the routine and what counts as a pass. The routine.
  2. Run it with a timer and fill in the score sheet. Run steps.
  3. Fix what breaks, one thing at a time, then start the count again. Fix steps.
  4. Save the code that passed. Save your work.

Robot for today: whichever robot is ready. ROBOT in StarterRobot.java must name it: PRACTICE_GOBILDA, PRACTICE_REV or BIOBUZZ_GOBILDA.

Before power

  • Everyone except the driver and the Stop person stays outside the taped area during a run.
  • One student drives. A different student keeps a hand near Stop on the Driver Station and may press it at any time without asking.
  • Press Stop and wait for everything to stop moving before you touch, load, measure or pick up the robot.
  • Clear a jam only with the robot switched off.
Stop first: if the robot goes the wrong way, something is loose, a ball jams, or the numbers on the screen look wrong, press Stop. Then work out why.

Steps and worksheets

The routine

Use the Meeting 5 tape field. A run lasts 2 minutes, the length of TELEOP in a match.

  1. Start with the back bumper on the start line, loaded with the balls the robot holds (no more than four).
  2. Drive to a shooting mark, aim, and shoot everything.
  3. Drive back behind the start line and stop. With the robot stopped, a student reloads it. On the BIOBUZZ robot, pick balls up from the floor with the intake instead.
  4. Repeat steps 2 and 3 until about 20 seconds are left.
  5. Finish at least partly inside the parking box before time runs out.

A run passes when: nobody had to press Stop, the program never crashed or froze, the robot scored at least the number of hits the team agrees now, and it ended in the parking box.

Hits needed for a pass: ________   Program used: ________

Why these things: in a match, tipping the hive is worth 20 points and ending TELEOP in the LOADING ZONE is worth 5. A robot may control at most four scoring elements at a time.

Run it

  1. Choose the driver and the Stop person. A third student runs a two-minute timer and calls “20 seconds”.
  2. INIT, choose the target if the program asks, Start the program and the timer together.
  3. Nobody coaches the driver during the run.
  4. At two minutes the driver puts the gamepad down. Press Stop.
  5. Fill in one row. Change drivers. Go again.

The count goes back to zero after a failed run and after any change to the code.

Fix one thing at a time

  1. Pick the problem that failed the most runs.
  2. Use the five steps from Meeting 7: observe, guess, check, change one thing, conclude.
  3. Run again. Start counting from one.
  4. If a feature keeps failing and cannot be fixed today, the team may switch it off, for example by using the baseline TeleOp without aiming. Write down what was switched off and why. Driving and Stop are never switched off.

Problems you did not get to go in the fault log.

Save your work

  • The score sheet shows whether the routine passed three times in a row, and what failed if it did not.
  • Any feature the team switched off is written down with the reason.
  • Commit the code that passed with a message you will recognize later, for example “TeleOp passed 3 runs”. This is the version to go back to if something breaks.

Meeting 9 starts autonomous with one small drive. A TeleOp safety problem that is still open gets fixed first.

Mentor preparation

  1. Rebuild the Meeting 5 tape field: wall target, start line, shooting marks, parking box.
  2. Bring a timer, plenty of balls, and at least two charged batteries. Swap the battery between sets of runs.
  3. Do not add features today. If students want one, write it on a list for later.
  4. Print the score sheet with the page’s print button.

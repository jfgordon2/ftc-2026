Trace it. Evaluate it. Rebuild it.

Students identify the exact robot and source path, make team decisions from evidence, measure the assembled system, rebuild TeleOp and Autonomous behavior, and prove an event-ready handoff.

Practice now, build as we go

We start with last season’s fully assembled REV and goBILDA StarterBots. Each keeps its own program, configuration, and test records. We will build a BIOBUZZ competition robot with a required launcher while the practice robots support learning.

Meetings 4-13 reserve 35 minutes of each three-hour meeting for physical build work. Keep one powered station under the coach’s supervision. A practice pass does not qualify a different robot; repeat affected checks when moving to the new build.

Robot selection, build milestones, and transfer checklist

Course purpose

By the first event, every student can trace the exact robot code, rebuild required behavior, test it safely, recover a known-good version, and explain the evidence.

Java is the primary path. Every lesson advances team code for the selected robot while preserving a tested fallback. Work stays in TeamCode; official files under FtcRobotController are not team editing targets.

Evidence labels

Sources and claims are cited in-line with evidence labels. Source F is a documented fact within the named source and scope. Team choice D is a BIOBUZZ decision with a recorded rationale. Measure it M is a result that only the identified robot and procedure can establish. An unperformed M claim remains pending delivery evidence.

Robot testing

Supported test: the robot or frame is secured on stable support, with every wheel clear of the support, floor, people, wires, and loose objects.

Travel test: the robot is on the game arena at a marked start, following a marked route to a marked stop, with a marked and cleared exclusion area.

Shared controls: for every powered test, name the Driver Station operator and a different Stop owner, keep everyone outside the exclusion area while the robot is live, define explicit safe output and stopping conditions, and record evidence. Use stations or workstreams for team rotations.

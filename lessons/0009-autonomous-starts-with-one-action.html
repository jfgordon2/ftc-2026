Today’s goal

Leave with a one-action autonomous that drives off the start line, stops by itself, and does the same thing three times in a row.

Autonomous means no driver. The program has to start the move, notice when it is finished, and give up safely if something goes wrong. Today’s program is small enough to read in five minutes, and it is already worth points: leaving the field wall in AUTO scores LEAVE.

Start here

  1. Read the program and predict what it does. Reading steps.
  2. Run it and measure. Run steps.
  3. Change one number, then make it fail safely on purpose. Change steps.
  4. Save. Save your work.

Robot for today: whichever robot is ready. ROBOT in StarterRobot.java must name it: PRACTICE_GOBILDA, PRACTICE_REV or BIOBUZZ_GOBILDA.

One robot runs at a time. Students who are not at the robot read the code for the next step, fill in predictions, or work on the build. Swap jobs after every test.

Before power

  • Mark a clear lane on the floor. Nobody stands in it while an autonomous program runs.
  • In autonomous nobody is driving, so the Stop person watches the robot, not the screen.
  • One student drives. A different student keeps a hand near Stop on the Driver Station and may press it at any time without asking.
  • Press Stop and wait for everything to stop moving before you touch, load, measure or pick up the robot.
  • Clear a jam only with the robot switched off.
Stop first: if the robot goes the wrong way, something is loose, a ball jams, or the numbers on the screen look wrong, press Stop. Then work out why.

Steps and worksheets

Words you need

Autonomous: the robot runs with no driver. Command: one move the program asks for, such as “drive 12 inches”. Timeout: a time limit after which the program gives up on a command. FAULT: the command could not finish, so the robot stopped.

Read the program

Program: Autonomous One Action (AutoOneAction.java).

MethodWhen it runsWhat it does here
init()Once, when INIT is pressedFinds the motors and the heading sensor.
start()Once, when Start is pressedGives the drive command once. It does not wait for the robot to arrive.
loop()Many times a secondLooks at the program’s state. In MOVE it asks the drive how the command is going. DONE and FAULT mean there is nothing left to do.
stop()Once, when Stop is pressed or time is upStops every motor.

Answer with your partner before running it:

  1. Which line says how far to drive?
  2. The program is always in one of three states. What are they, and which line changes MOVE to DONE?
  3. The drive gives up after 4 seconds. Why is that safer than waiting forever?
  4. Why does the program not use a line like “wait until done”? (Hint: what else has to keep happening while the robot moves?)

Run it and measure

  1. Put the robot’s pointer on a tape mark with a clear lane ahead. Stop person ready.
  2. INIT. Read the plan on the screen. Start.
  3. When State on the screen says DONE, press Stop. Measure from the mark to the pointer.
  4. Carry the robot back to the mark. Run it twice more.
  5. Is the distance the same each time? Is it what the code asked for?

Change one number, then make it fail safely

  1. Change LEAVE_INCHES to 24. Build, run, measure. Write the row.
  2. Try a negative number. Predict which way the robot goes first.
  3. Now ask for 72 inches in a lane at least 6 feet long. The robot drives slowly, so it probably cannot get there in 4 seconds. Predict what the screen will say, then run it with a hand on Stop.
  4. Put LEAVE_INCHES back to a distance that clearly moves the whole robot off the start line.

A FAULT is the program protecting the robot. The fix is to find out why the move could not finish, not to make the time limit longer.

In a match: AUTO lasts 30 seconds. The robot starts touching the field wall with four POLLEN. Moving so it no longer touches the wall is LEAVE, 3 points.

Save your work

  • The one-action autonomous runs, stops by itself, and stops when Stop is pressed.
  • The worksheet shows how far the robot went on three runs from the same mark.
  • The code builds with a sensible LEAVE_INCHES. Commit it with a short message, for example “Meeting 9 one-action auto”.

Meeting 10 works out why the robot knows how far it has gone, and corrects the number it uses.

Mentor preparation

  1. The autonomous programs stay still until MOUNTING_CONFIRMED (in Heading.java) and MOTION_ENABLED (in StarterRobot.java) are true. Do the Hub-direction and drive-direction checks from the Meeting 5 setup guide on the robot in use first.
  2. Tape a start mark and a clear lane at least 6 feet long.
  3. Bring a tape measure and charged batteries.
  4. This program stays in the code all season as the simplest backup autonomous. The full autonomous in Meeting 11 is the same program with a list of steps, so time spent reading this one is not wasted.

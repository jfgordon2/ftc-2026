Today’s goal

Leave knowing that every student can make a small change, get it onto the robot, test it safely, and put the event code back.

This is the last meeting before the event. Nothing new is added to the robot. Each student takes a turn at the laptop with no help from the mentor’s hands, while the rest of the team checks that the saved code builds on a second laptop and finishes packing.

Start here

  1. Solo turn: change, build, deploy, test, undo. Solo steps.
  2. Fresh copy: prove the saved code builds from scratch. Fresh copy steps.
  3. Hand over: what the team needs to know at the event and next season. Handover notes.
  4. Save. Save your work.

Before power

  • Solo turns run the robot on blocks. A partner is always the Stop person.
  • The practice change is never left on the robot. The event code goes back on at the end of every turn.
  • One student drives. A different student keeps a hand near Stop on the Driver Station and may press it at any time without asking.
  • Press Stop and wait for everything to stop moving before you touch, load, measure or pick up the robot.
  • Clear a jam only with the robot switched off.
Stop first: if the robot goes the wrong way, something is loose, a ball jams, or the numbers on the screen look wrong, press Stop. Then work out why.

Steps and worksheets

Your solo turn

The mentor does not touch the keyboard or the Driver Station. You may ask questions.

  1. Open the project. Check you are on the event code: the last commit message should be the one the team wrote in Meeting 15.
  2. Pick one control. Explain to your partner the path from the gamepad to the motor: which line reads the input, which line decides, which line moves the motor, and what happens on Stop.
  3. Make one harmless change: add a telemetry line that shows a short message of your choice.
  4. Build it and deploy it to the robot.
  5. Robot on blocks. INIT, Start. Show your message on the Driver Station. Press Stop.
  6. Undo the change so the code matches the event code again. Build and deploy again.
  7. Run once more to show your message is gone and the robot still works.
  8. Find one fault. The mentor sets up one problem from the Meeting 14 list. Use the five steps.

Keep your own copy of this checklist. Anything you could not do alone is what to practice next.

Prove the saved code builds from scratch

If the only working copy is on one laptop, the team is one spilled drink from having no robot code. While solo turns happen:

  1. On a second laptop, download the team repository into a new, empty folder.
  2. Open it in Android Studio and build it without changing anything.
  3. If it does not build, find out what is missing from the repository, add it on the first laptop, commit, and try again.
  4. If there is time, deploy from the second laptop and run the robot on blocks.

See Android Studio setup and deploy if the second laptop needs setting up.

Save your work

  • Every student has had a solo turn and has their own checklist.
  • The saved code builds from a fresh copy on a second laptop.
  • The handover notes are written and packed with the robot.
  • The robot has the event code on it, and one last run on blocks shows it works.

Next is the event. Bring the troubleshooting guide, the handover notes, and the packed kit.

Mentor preparation

  1. Make sure the team repository is pushed to GitHub and that a second laptop is available with Android Studio installed.
  2. Decide the order of solo turns so nervous students are not left until last.
  3. Prepare one easy fault per student from the Meeting 14 list.
  4. Keep your hands off the keyboard and the Driver Station. Answer questions with questions where you can.

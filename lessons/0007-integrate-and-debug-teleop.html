Today’s goal

Leave with one TeleOp that drives, aims and shoots, and with one fault found and fixed using the five debugging steps.

Putting working parts together is where new problems show up. Today we move to the aiming TeleOp, bring over the slow mode from Meeting 6, and practice a calm way to find out what is wrong.

Start here

  1. Run the aiming TeleOp and learn its controls. Aiming steps.
  2. Combine: add your Meeting 6 slow mode to it. Combine steps.
  3. Debug: the mentor plants one fault; you find it. Debugging steps.
  4. Save. Save your work.

Robot for today: whichever robot is ready. ROBOT in StarterRobot.java must name it: PRACTICE_GOBILDA, PRACTICE_REV or BIOBUZZ_GOBILDA.

One robot runs at a time. Students who are not at the robot read the code for the next step, fill in predictions, or work on the build. Swap jobs after every test.

Before power

  • The first time new code runs, the robot sits on blocks with its drive wheels off the floor.
  • Everyone stands behind the robot when the launcher can spin. Use the Meeting 5 tape wall or another safe target.
  • One student drives. A different student keeps a hand near Stop on the Driver Station and may press it at any time without asking.
  • Press Stop and wait for everything to stop moving before you touch, load, measure or pick up the robot.
  • Clear a jam only with the robot switched off.
Stop first: if the robot goes the wrong way, something is loose, a ball jams, or the numbers on the screen look wrong, press Stop. Then work out why.

Steps and worksheets

Words you need

Bearing: how far left or right the tags are from straight ahead, in degrees. Aimed: the bearing has stayed near zero for a moment. Symptom: what you can see going wrong. Cause: the thing that makes it go wrong. One cause can have several symptoms.

Run the aiming TeleOp

Program: TeleOp with Aiming (TeleOpAim.java). It is the baseline plus the camera.

ControlWhat it does
D-pad during INITChoose the target. LEFT/RIGHT is red/blue; UP/DOWN is far-side/audience-side cell. Pick the one that is printed on your wall.
SticksDrive, as before.
Hold AThe robot turns to face the tags and holds still. Let go to drive again.
Hold right bumperSpin the launcher. While A is held, the speed comes from the Meeting 5 table for the range the camera reads.
Hold A and right bumper togetherFeed, but only when the robot is aimed, the range is one the table covers, and the wheel is at speed.
  1. INIT and choose the target. The screen should show the tags as seen.
  2. Start. Drive to a Meeting 5 shooting mark. Hold A. Watch the bearing number go toward zero.
  3. Keep A held and add the right bumper. Read “wanted / measured” speed on the screen.
  4. Shoot five. Count hits. Move to another mark and repeat.
  5. Cover the tags with your hand while holding A and the bumper. The feeder must stop.

If it will not feed, read the screen from top to bottom: target seen, aimed, range, speed, and whether motion and feed are switched on. The first line that says no is the reason.

Add your slow mode

In TeleOpAim.java, find updateDriving(). Change the stick-driving line the same way you did in Meeting 6 so the left bumper slows the robot. Do not change the line that runs while A is held.

  1. Build, deploy, test on blocks.
  2. Check slow mode works.
  3. Check holding A still aims. Slow mode must not change aiming.
  4. Check shooting still works.

Find a fault on purpose

Send one pair out of the room. The mentor makes one change from the mentor’s list. The pair comes back and finds it. No guessing by changing things at random.

  1. Observe. What exactly happens? What did you expect? Write both down. Copy any error message word for word.
  2. Guess. Write one sentence: “I think … because …”.
  3. Check. Look at something that would prove the guess right or wrong: a telemetry line, the configuration screen, a cable, one line of code. Add a telemetry line if you need one.
  4. Change one thing. Only one. Build and test again.
  5. Conclude. Fixed? Run the same test that failed. Not fixed? Undo the change and go back to step 2.

Save your work

  • The aiming TeleOp drives, aims and shoots, with slow mode working.
  • Anything still wrong is in the fault log: what you saw and what you will try next.
  • The code builds. Commit it with a short message, for example “Meeting 7 aim TeleOp with slow mode”.

Mentor preparation

  1. The aiming TeleOp needs MOTION_ENABLED = true to turn by itself and FEED_ENABLED = true to feed. Both are in StarterRobot.java. Set them after the checks in the Meeting 5 setup guide.
  2. The speed table in ShooterCalibration.java should hold the Meeting 5 rows for the robot in use. With an empty table the launcher still spins at its normal speed, but the aiming TeleOp will not feed.
  3. Rebuild the Meeting 5 tape wall, or set up another safe target with the printed tags.
  4. Faults to plant, one at a time (each is easy to undo):
    • Unplug the webcam.
    • Select the wrong target in INIT, or cover one printed tag sheet.
    • Set FEED_ENABLED back to false.
    • Swap FORWARD and REVERSE for one drive motor in StarterRobot.java (test on blocks).
    • Rename launcher in the Driver Station configuration.
    • Leave the gamepad unassigned (do not press Start + A).

Words you need today

Encoder count
One reported unit of shaft rotation. A count is not an inch and does not by itself identify floor position.
Motor revolution
One complete turn of the motor shaft where the encoder is measured.
Gearbox output revolution
One complete turn of the gearbox output shaft. Gearing can make its revolution count differ from the motor's.
Wheel revolution
One complete turn of the wheel. Another gear, chain, or belt stage can make this differ from the gearbox output.
Surface travel
The distance the wheel or assembled robot moves along the test surface. Compression and slip can make it differ from ideal geometry.
Assembled ratio
The verified number of motor revolutions for one wheel revolution through every installed transmission stage.
Track width
The measured left-to-right distance between the drivetrain's effective wheel paths used for the point-turn estimate.
Target and current position
The requested encoder position and the position reported now. Their difference shows remaining count error.
Motor run mode
A motor-controller setting that tells the SDK how to use a power command and encoder feedback. The team must identify the exact mode already used by each drive motor in its qualified normal drive code.
RUN_TO_POSITION
RUN_TO_POSITION tells the motor controller to use encoder feedback to move toward a target position while power is applied. Code sets the target before entering this mode. It is temporary for today's bounded action, not a universal normal drive mode.
Mode recheck
The zero-output getMode() comparison already established by the team's earlier motor evidence. It is not introduced in Meeting 10; today students repeat it immediately before an encoder action and compare it with the Meeting 2 expected-mode record, Meeting 9 mode recheck/handoff, and current qualified team code.
Saved normal mode
The exact DcMotor.RunMode assigned from that passing immediate recheck before any switch to RUN_TO_POSITION. Each motor can have its own saved value.
Tolerance
A team-selected acceptable result range declared before seeing trial results.
Mode restoration
After any action exit, command zero and set each motor back to its own saved normal mode. Then read getMode() again and record whether restoration matched.

  • Use a supported test in the game arena for the visible-revolution and sign checks: secure the frame on stable support with every wheel clear of support, floor, people, wires, and loose objects.
  • Use a Travel test in the game arena for each segment: mark the start, intended route, stop boundary, exclusion area, observer position, and powered-off reset path.
  • Press Stop, verify no motion, switch off the Hub, and disconnect the battery before marking, measuring, touching, or adjusting any wheel, drivetrain part, wire, support, or field reference.

Measure before writing distance code

Complete these steps in order. A blank, unexplained mismatch, or unverified installed ratio blocks distance and turn code.

  1. Freeze the identity: record robot revision, active configuration, OpMode/code identity, every drive motor and encoder model, configured motor type, Hub/port, wheel and tire, gearbox, external gears/sprockets/pulleys, surface, battery acceptance, date, student, and checker. Success: every exact part and transmission stage is named or marked blocked.
  2. Retrieve the upstream mode records: for every mapped drive motor, copy the expected enum and row ID from the Meeting 2 expected-mode record. Then copy the mode, row ID, exact code/configuration identity, and blocker status from the Meeting 9 mode recheck/handoff. Locate the exact current qualified team-code line or initialization path that sets that motor's mode. Success: all three records identify the same motor, configuration, code lineage, and expected enum. If either upstream record lacks the named field or row ID, return that interface gap to its owner and block powered M10 work; do not recreate the missing upstream evidence here.
  3. Repeat the established recheck immediately before action: at explicit zero output, display each motor's current getMode() and compare it separately with the Meeting 2 expected mode, Meeting 9 rechecked mode, and current qualified-code declaration. Success: all four values agree before the current value is saved. If any value is unknown, the records disagree, the identity changed, or the live readback is unexpectedly RUN_TO_POSITION, command zero, block powered testing, and resolve the discrepancy from upstream records, qualified team code, and pinned SDK/API evidence. Do not choose RUN_USING_ENCODER or RUN_WITHOUT_ENCODER merely because a sample uses it.
  4. Separate the rotations: draw and label encoder counts -> motor shaft -> gearbox output -> external transmission -> wheel -> surface travel. Write the published ratio for each matching documented stage and the assembled direction of motion. Success: no student uses motor revolution and wheel revolution as synonyms.
  5. Mark one visible wheel revolution: while powered down, place one removable witness mark at a named wheel and frame reference. Record the raw encoder start. Complete one approved low-output supported test until the mark returns once to the reference; command zero and press Stop. Record raw end and signed change as end - start. Success: the observer saw exactly one wheel revolution and the record has raw values, sign, command source, zero, and Stop proof.
  6. Repeat and reconcile: perform three one-revolution observations from the same mark without discarding inconvenient valid rows. Compare observed absolute counts with the count predicted from exact manufacturer counts and published gearing. Success: the team explains agreement within a predeclared tolerance or blocks the conversion and investigates identity, gearing, missed revolutions, sign, or looseness.
  7. Measure loaded wheel diameter: with power disconnected and the robot resting as specified by the team's method, measure at three named orientations in one stated unit. Record tire condition and compression; calculate the team's stated representative diameter and circumference. Success: every input, method, unit, and calculation is visible.
  8. Measure track width: use named left and right effective wheel-path references, measure three times in the same distance unit, and record the team's stated representative value. Do not silently substitute outer tire width or chassis width. Success: another pair can reproduce both references.
  9. Verify signs: in separate brief supported checks, predict and observe the encoder change for each side when commanded in the robot's forward direction. Record the command-space sign convention used by the reusable method. Success: forward, backward, and left-turn target signs can be derived rather than guessed.

Use the five-formula ladder

Keep units beside every value and do not cancel them mentally. Formula structure is a documented fact; exact product specifications are manufacturer facts; installed geometry and observed counts are measurements; and tolerances are team decisions made before results.

1. Wheel circumference

wheel circumference = pi * measured wheel diameter

Units: distance/revolution = dimensionless * distance. Use the team's measured loaded diameter, not a catalog nominal diameter.

Source M10-F06 Measure it M10-M01

2. Counts per wheel revolution

counts per wheel revolution = motor counts per revolution * motor revolutions per wheel revolution

Manufacturer counts and published gearing are F inputs from the one matching identity path: REV M10-F04 or goBILDA M10-F05, never both by default. The team's installed-stage trace, visible-revolution count, and verified assembled ratio are M inputs.

Source M10-F04 Source M10-F05 Source M10-F06 Measure it M10-M01

3. Counts per distance

counts per distance = counts per wheel revolution / wheel circumference

Units: counts/revolution divided by distance/revolution = counts/distance. State whether distance is inches, centimeters, or another single chosen unit.

Source M10-F06 Measure it M10-M01

4. Target counts

target counts = requested distance * counts per distance

Units: signed distance * counts/distance = signed count change. Add that change to each motor's current position using the team's verified command-space signs.

Source M10-F06 Measure it M10-M01

5. Point-turn wheel path

point-turn wheel path = pi * track width * requested angle / 360

For a left point turn, the two sides receive equal path magnitudes in opposite command-space directions. Feed each signed wheel path into the target-counts formula.

// Method intent; expand left/right to every mapped drive motor.
void driveWheelDistances(double leftDistance, double rightDistance,
                         double testedPower, double testedTimeout) {
    // Populate only from the named upstream rows and qualified code review.
    DcMotor.RunMode meeting2LeftExpectedMode = MEETING_2_LEFT_EXPECTED_MODE;
    DcMotor.RunMode meeting2RightExpectedMode = MEETING_2_RIGHT_EXPECTED_MODE;
    DcMotor.RunMode meeting9LeftRecheckedMode = MEETING_9_LEFT_RECHECKED_MODE;
    DcMotor.RunMode meeting9RightRecheckedMode = MEETING_9_RIGHT_RECHECKED_MODE;
    DcMotor.RunMode qualifiedCodeLeftMode = QUALIFIED_CODE_LEFT_MODE;
    DcMotor.RunMode qualifiedCodeRightMode = QUALIFIED_CODE_RIGHT_MODE;

    // Keep output at zero while repeating the upstream getMode() check.
    leftDrive.setPower(0.0);
    rightDrive.setPower(0.0);
    DcMotor.RunMode leftModeRecheck = leftDrive.getMode();
    DcMotor.RunMode rightModeRecheck = rightDrive.getMode();
    boolean leftModeMatches = leftModeRecheck == meeting2LeftExpectedMode
            && leftModeRecheck == meeting9LeftRecheckedMode
            && leftModeRecheck == qualifiedCodeLeftMode;
    boolean rightModeMatches = rightModeRecheck == meeting2RightExpectedMode
            && rightModeRecheck == meeting9RightRecheckedMode
            && rightModeRecheck == qualifiedCodeRightMode;

    if (!UPSTREAM_MODE_RECORDS_VERIFIED
            || !leftModeMatches || !rightModeMatches
            || leftModeRecheck == DcMotor.RunMode.RUN_TO_POSITION
            || rightModeRecheck == DcMotor.RunMode.RUN_TO_POSITION) {
        leftDrive.setPower(0.0);
        rightDrive.setPower(0.0);
        telemetry.addData("Action blocked", "Resolve mode progression");
        telemetry.update();
        return;
    }

    DcMotor.RunMode savedLeftMode = leftModeRecheck;
    DcMotor.RunMode savedRightMode = rightModeRecheck;

    String exitReason = "INACTIVE_BEFORE_ACTION";
    try {
        if (!opModeIsActive()) return;

        int leftChange = (int) Math.round(
                leftDistance * COUNTS_PER_DISTANCE * LEFT_FORWARD_SIGN);
        int rightChange = (int) Math.round(
                rightDistance * COUNTS_PER_DISTANCE * RIGHT_FORWARD_SIGN);
        int leftTarget = leftDrive.getCurrentPosition() + leftChange;
        int rightTarget = rightDrive.getCurrentPosition() + rightChange;

        leftDrive.setTargetPosition(leftTarget);  // target before position mode
        rightDrive.setTargetPosition(rightTarget);
        leftDrive.setMode(DcMotor.RunMode.RUN_TO_POSITION);
        rightDrive.setMode(DcMotor.RunMode.RUN_TO_POSITION);
        timer.reset();

        leftDrive.setPower(Math.abs(testedPower));
        rightDrive.setPower(Math.abs(testedPower));
        while (opModeIsActive()
                && timer.seconds() < testedTimeout
                && (leftDrive.isBusy() || rightDrive.isBusy())) {
            telemetry.addData("Left target/current/busy", "%d / %d / %b",
                    leftTarget, leftDrive.getCurrentPosition(), leftDrive.isBusy());
            telemetry.addData("Right target/current/busy", "%d / %d / %b",
                    rightTarget, rightDrive.getCurrentPosition(), rightDrive.isBusy());
            telemetry.addData("Saved modes", "%s / %s",
                    savedLeftMode, savedRightMode);
            telemetry.addData("Elapsed/timeout", "%f / %f",
                    timer.seconds(), testedTimeout);
            telemetry.update();
            // The observer presses Driver Station Stop for any abort condition.
        }
        exitReason = !opModeIsActive() ? "STOP_OR_ABORT"
                : timer.seconds() >= testedTimeout ? "TIMEOUT"
                : "TARGET_REACHED";
    } finally {
        leftDrive.setPower(0.0);
        rightDrive.setPower(0.0);
        leftDrive.setMode(savedLeftMode);
        rightDrive.setMode(savedRightMode);
        telemetry.addData("Exit reason", exitReason);
        telemetry.addData("Left saved/restored", "%s / %s",
                savedLeftMode, leftDrive.getMode());
        telemetry.addData("Right saved/restored", "%s / %s",
                savedRightMode, rightDrive.getMode());
        telemetry.update();
    }
}

void driveDistance(double signedDistance, double power, double timeout) {
    driveWheelDistances(signedDistance, signedDistance, power, timeout);
}

void turnLeftDegrees(double angle, double power, double timeout) {
    double path = Math.PI * MEASURED_TRACK_WIDTH * angle / 360.0;
    driveWheelDistances(-path, path, power, timeout);
}

Before power

  • The first time new code runs, the robot sits on blocks with its drive wheels off the floor.
  • Everyone stands behind the robot when the launcher can spin.
  • One student drives. A different student keeps a hand near Stop on the Driver Station and may press it at any time without asking.
  • Press Stop and wait for everything to stop moving before you touch, load, measure or pick up the robot.
  • Clear a jam only with the robot switched off.
Stop first: if the robot goes the wrong way, something is loose, a ball jams, or the numbers on the screen look wrong, press Stop. Then work out why.

Steps and worksheets

Words you need

Proportional input: a stick or trigger; how far you push changes how much happens. Held input: something happens only while the button is down. One-press input: one tap changes something that stays changed. Edge: the moment a button goes from up to down. Conflict: two controls asking for opposite things.

Read the baseline TeleOp

Program: TeleOp (TeleOpBasic.java). Its loop() runs many times a second. Each pass reads the gamepad and decides every output again.

ControlPatternWhat the code does
Left stick up / downProportionalDrive forward or back. Further push, more power.
Right stick left / rightProportionalTurn.
Right trigger / left triggerProportionalIntake in / out. The code subtracts one from the other. BIOBUZZ robot only; the practice robots have no intake.
Hold right bumperHeldSpin the launcher. Once it is fast enough, the feeder runs too.

On a practice robot, holding the right bumper feeds every ball it has. That is expected.

Add three controls, one at a time

Edit TeleOpBasic.java. After each change: build, put it on the robot, test on blocks, and fill in its worksheet row.

1. Show the launcher speed

Add this line next to the other telemetry line in loop():

telemetry.addData("Launcher ticks/second", "%.0f", robot.launcher.getVelocity());

2. Slow mode (a held input)

While the left bumper is held, driving is gentler. Replace the line robot.arcadeDrive(forward, rotate); with:

double scale = 1.0;
if (gamepad1.left_bumper) {
    scale = 0.4;
}
robot.arcadeDrive(forward * scale, rotate * scale);

Predict first: what happens the moment you let go of the bumper while the stick is pushed?

3. Keep the launcher on (a one-press input)

One tap of X turns the launcher on and leaves it on. Another tap turns it off. Add two fields near the top of the class, below robot:

private boolean launcherOn;
private boolean wasX;

Then replace the line boolean spin = gamepad1.right_bumper; with:

boolean xPressed = gamepad1.x && !wasX;   // true only on the loop where X goes down
wasX = gamepad1.x;
if (xPressed) {
    launcherOn = !launcherOn;
}
boolean spin = launcherOn || gamepad1.right_bumper;
telemetry.addData("Launcher kept on", launcherOn);

Test: hold X down for three seconds. The launcher should change once, not flicker. Why does wasX make that work?

The feeder still runs only while the right bumper is held, so a tap of X never fires a ball by itself.

Save your work

  • Each control on the worksheet has a “what really happened” entry.
  • A control that is not finished is switched off in the code, with a one-line comment saying what is left.
  • The code builds. Commit it with a short message, for example “Meeting 6 slow mode and launcher toggle”.
